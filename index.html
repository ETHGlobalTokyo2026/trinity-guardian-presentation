01
The problem 問題

x402 made agent payments one line of code. Nobody gave the wallet a conscience.

  • The agent holds its own key and USDC — it signs 402 challenges autonomously, all day, unattended.
  • A prompt-injected or buggy agent pays any endpoint that asks — including ones that scam, drain, or vanish.
  • Spending limits in a config file live inside the very machine an attacker already owns.
門

Whatever stops the payment must live outside the runtime — and outlive it.

rights on-chain · screening at the edge · a human on the phone

02
The concept 三層

Three gates, in order. None can overrule another.

Layer 1 · 一

ENS

the gate — 門

The right to pay lives on-chain. A spend role on the agent's own name under agents.trinityguard.eth. No role — no signature, ever. Revoking it is a kill switch the agent cannot argue with.

Layer 2 · 二

Intercepta

the checkpoint — 関所

Before any signature: screen the payTo address, the token, the auth message — live API, not a mock list. Green and under cap → pay. Red or over cap → escalate or refuse, with the reason on screen.

Layer 3 · 三

World ID

the human approver — 人

Risky or over-cap payments stop and wait for the owner's phone. A real World ID verification — approve with a bound, or deny and log why. A meaningful action, not a login screen.

05
Layer 2 · 二 関所

Intercepta — the checkpoint screens every payment, live.

  • quick-scan-address on the payTo — is this endpoint a known scam, honeypot, or burner cluster?
  • scan-token + scan-message on the asset and the x402 auth message — nothing signs blind.
  • Mainnet screening even while payments run on testnet — verdicts are real, not a fixture.
青

Green + under cap → the agent signs automatically. No human in the loop — that's the point.

黄

Red or over cap → the payment stops. Reason on screen; over-cap escalates to Layer 3.

06
Layer 3 · 三 人

World ID — when it matters, a human decides.

  • Triggered by soft fail: a flagged counterparty, or an amount past dailyCap.
  • Complete journey: request → owner verifies in World App → validated → protected action. QR + user code on the dashboard, expiry countdown ticking.
  • Owner can approve bounded ("this once, this much") or deny with a reason — both are first-class outcomes, both are logged.
人

A meaningful action is one that moves money — not a login screen.

World ID for Agents · sandbox.auth.world.org · the denied path is a headline demo, not an edge case
